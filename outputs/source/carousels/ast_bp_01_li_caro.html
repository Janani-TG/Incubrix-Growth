PHASE 1: THE INGESTION VULNERABILITY

The Client-Side Telemetry Trap

Why traditional client-side JavaScript analytics fails in modern SaaS production:

1. Ad Blocker Interception

15–25% of client-side tracking events silently fail to reach third-party analytics endpoints due to browser ad blockers and strict tracking prevention.

2. Uncontrolled Schema Drift

Frontend UI refactors rename buttons or omit payload parameters, silently corrupting historical funnel metrics without triggering build errors.

3. Double-Counted Conversions

Mobile network retries resend registration calls, double-counting signups and skewing Day-1 retention cohorts.

PHASE 2: NON-BLOCKING EVENT STREAM

Asynchronous Ingestion Architecture

Decouple user response latency from analytical processing with a distributed event queue:

Client Action (HTTP POST)
↓ (P99 < 15ms Response)
Edge Gateway (FastAPI / Envoy → HTTP 202)
↓ (Asynchronous Buffer)
Distributed Queue (Redis / SQS FIFO)
↓ (Validated Consumer)
Worker Engine (Schema Check & Dedupe)
↓ (Immutable Storage)
Analytics DB (PostgreSQL / ClickHouse)
LATENCY GUARDRAIL

The edge gateway accepts events and immediately replies with HTTP 202 Accepted. User signups and payments are never blocked by analytical database writes.

PHASE 3: IDEMPOTENT RECORDING

SHA-256 Fingerprint Deduplication

Guarantee exact-once recording semantics across all cohort analysis tables:

def compute_fingerprint(event: TelemetryPayload) -> str:
  raw = f"{event.user_id}|{event.name}|{event.utc_ts}"
  return hashlib.sha256(raw.encode()).hexdigest()
DATABASE UNIQUENESS CONSTRAINT

A composite unique index on (fingerprint) ensures that duplicate network dispatches are safely ignored at the database layer without throwing exceptions or inflating event counts.
